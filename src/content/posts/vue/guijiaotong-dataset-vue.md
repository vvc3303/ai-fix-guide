在 Vue 页面里渲染桂教通的业务模型数据，最坑的是**平台没有公开接口文档**。直接照抄普通请求写法，就是一路报错、返回空。

## 报错现象

- Vue 页面**无法实时拉取**桂教通业务模型数据
- 自己写请求代码渲染**饼图、数据卡片**时**语法报错**
- 接口通了但**数据返回为空**

## 原因分析

桂教通这类低代码平台，业务模型数据**不能直接当普通 REST 接口调**。直接写请求代码有三大问题：

1. **没有原生接口文档**：字段、鉴权、地址全靠猜
2. **语法报错**：请求写法和平台要求不一致
3. **数据为空**：即使请求通了，也拿不到平台统计好的聚合结果

## 解决步骤

**改用平台内置的数据集统计函数**，而不是手写请求：

1. 在桂教通后台，找到**数据集 / 数据模型**管理
2. 优先使用平台**内置的统计函数**绑定图表组件（饼图、数据卡片都能直接挂数据集）
3. 平台内置函数搞不定的聚合逻辑，**单独创建 SQL 数据集**做聚合统计：

```sql
-- 例子：按业务模型分组统计数量
SELECT category, COUNT(*) AS cnt
FROM business_model
GROUP BY category
```

4. 把 SQL 数据集绑定到 Vue 页面的**图表组件**，由平台负责取数和渲染。

## 效果验证

- 饼图、数据卡片正常渲染，不再是空的
- Vue 页面无语法报错
- 数据与平台后台统计一致

## 排错速查表

| 现象 | 处理 |
|------|------|
| 语法报错 | 别手写请求，用内置数据集函数 |
| 数据为空 | 单独建 SQL 数据集聚合 |
| 统计不一致 | 核对数据集绑定的是同一个数据源 |

> 核心经验：**低代码平台的数据，先问「有没有数据集函数」再问「接口在哪」**。手写请求是最后手段，内置数据集才是正路。
