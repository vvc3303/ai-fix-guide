在 CCSwitch 里加自定义服务商，本以为是填几个框的事，结果「保存失败」+「部分输入框填不进内容」，折腾到怀疑人生。

## 报错现象

- 新增自定义服务商时**保存失败**
- 中转 API 参数格式不匹配，**部分输入框无法正常填写**
- 提示的信息和你在别处填的不一致

## 原因分析

把两种协议格式**混着填了**：

- **原生 Claude 协议**：用 Anthropic 的调用方式和参数结构
- **OpenAI 兼容协议**：`/v1/chat/completions` 这套通用格式

一个服务商配置里既要 Claude 协议又要 OpenAI 兼容协议，参数对不上，表单自然校验失败、保存不了。

## 解决步骤

**统一使用 OpenAI 兼容格式填写中转地址、密钥、模型名称**：

| 配置项 | 填法 |
|--------|------|
| 中转地址 Base URL | `https://xxx.com/v1`（带 `/v1`） |
| 密钥 API Key | `sk-...` 中转服务商给的 Key |
| 模型名称 Model | 服务商模型列表里的**精确 id** |

关键点：

1. 全部字段用一个协议体系（OpenAI 兼容），**不要一半 Claude 一半 OpenAI**
2. 如果该服务商只支持原生 Claude 协议，就别选「OpenAI 兼容」模式的表单去填
3. 填完保存前，先用服务商给的「测试」按钮验证连通

## 效果验证

- 自定义服务商保存成功
- 表单各输入框都能正常填写
- 测试连通通过，能正常调用

## 排错速查表

| 现象 | 处理 |
|------|------|
| 保存失败 | 检查是否混用两种协议 |
| 输入框填不进 | 清掉旧格式内容，按 OpenAI 兼容统一重填 |
| 测试不通 | 核对 base_url 是否带 /v1 |

> 核心经验：**协议格式只能二选一，别混搭**。混用是 CCSwitch 自定义服务商报错的头号原因。
